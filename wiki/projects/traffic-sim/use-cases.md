# Use Cases: локальная разработка vs работа на сервере

> Правило разделения: локально — **итерация и код**, сервер — **ресурсоёмкое выполнение и демо**.

---

## 1. Локально → push → server-pull action

Используется когда результат работы — **код, конфиг или данные**, которые нужно воспроизводимо выполнить на сервере.

### MATSim

| Use Case | Что делает локально | Что запускает CI |
|---|---|---|
| Настройка сценария спроса | Редактирует `config.xml`: зоны, популяция, временные срезы | Запускает MATSim batch на полной сети Иркутска |
| Калибровка параметров | Меняет коэффициенты модальности, скорости агентов | Полный итерационный прогон (30–100 итераций) |
| Добавление нового сценария (закрытие моста) | Добавляет блокировку ребра в `network.xml` | MATSim → экспорт `plans.xml` → конвертация в `rou.xml` |
| Обновление данных населения | Кладёт новый `population.xml` из переписи | MATSim пересчитывает спрос, сохраняет артефакты |

### SUMO

| Use Case | Что делает локально | Что запускает CI |
|---|---|---|
| Разработка TraCI-скрипта | Пишет Python (светофоры, метрики, адаптивные алгоритмы), тестирует на малом bbox | Запускает полную симуляцию 3600 сек, сохраняет `metrics.json` |
| Изменение сети (netedit) | Правит `street.net.xml` — полосы, светофорные фазы, приоритеты | Валидация сети + прогон симуляции на обновлённой сети |
| Добавление ОТ маршрутов | Добавляет `bus_stops.xml`, `routes.rou.xml` | Симуляция с ОТ, проверка на конфликты |
| Настройка `.sumocfg` | Правит параметры: step-length, телепортация, seed | Full run + diff метрик с предыдущим прогоном |
| Подготовка OSM → net.xml | Выгружает OSM, запускает `netconvert` локально | CI проверяет связность сети, запускает smoke test |

### WeBots

| Use Case | Что делает локально | Что запускает CI |
|---|---|---|
| Создание/редактирование `.wbt` мира | Строит сцену в WeBots GUI: дороги, здания, светофоры, SumoInterface | Запускает WeBots headless, записывает `simulation.mp4` |
| Написание контроллера робота/агента (Python/C++) | Разрабатывает логику агента (RL-контроллер, сенсорная обработка) | Запускает симуляцию с контроллером, собирает reward/метрики |
| Обновление PROTO-объектов | Добавляет новый тип ТС или дорожного знака | CI проверяет загрузку сцены без ошибок |

## 2. Подключение к инструменту на сервере (docker container)

Используется когда нужно **интерактивно работать с GUI**, **наблюдать за живой симуляцией** или выполнять **разовые операции** без кода.

### MATSim

| Use Case | Как подключается | Зачем |
|---|---|---|
| Просмотр результатов прогона | SSH → `docker exec matsim bash` → просмотр `output/` | Изучить `plans.xml`, статистику итераций |
| Разовый debug-прогон | SSH → `make matsim-run` с временным конфигом | Проверить конкретную итерацию без коммита |

> MATSim — batch инструмент без GUI на сервере. Интерактивная работа минимальна.

---

### SUMO

| Use Case | Как подключается | Зачем |
|---|---|---|
| Визуальная отладка сети | `make sumo-gui` → браузер `http://webots-vm:6083/vnc.html` | Видеть как едут машины, найти узкие места визуально |
| Редактирование сети в netedit | `make sumo-netedit` → браузер | Исправить артефакты OSM, добавить полосу вручную |
| Интерактивный TraCI debug | SSH → `docker exec <user>-sumo bash` → `python3 debug_traci.py` | Проверить поведение конкретного перекрёстка в реальном времени |
| Просмотр симуляции другого пользователя | Браузер → `http://webots-vm:6084/vnc.html` (другой пользователь) | Ревью результатов коллеги без перезапуска |

---

### WeBots

| Use Case | Как подключается | Зачем |
|---|---|---|
| Просмотр 3D симуляции (демо) | Браузер → `http://webots-vm:1234` (streaming viewer) | Показать результат заказчику, студентам, на хакатоне |
| Отладка 3D мира в реальном времени | `make sumo-gui` (noVNC) + WeBots streaming в другой вкладке | Видеть SUMO трафик и 3D одновременно |
| Интерактивная настройка SumoInterface | Браузер → WeBots noVNC → изменить `maxVehicles`, `radius` в GUI | Быстро подобрать параметры без перезапуска |
| Живой RL эксперимент | SSH → `docker exec webots bash` → запуск агента вручную | Отладить reward-функцию, посмотреть поведение агента |

## Сводная таблица выбора подхода

| Критерий | Локально → CI | Подключение к серверу |
|---|---|---|
| Результат — код/конфиг | ✅ | — |
| Нужна воспроизводимость | ✅ | — |
| Требуются большие ресурсы (RAM, CPU) | ✅ (CI на сервере) | — |
| Нужен GUI для отладки | — | ✅ |
| Разовая операция без коммита | — | ✅ |
| Демо для аудитории | — | ✅ (streaming) |
| Итерация > 10 раз в день | ✅ (локально + fast CI) | — |
| Нужно видеть чужую симуляцию | — | ✅ |
